================================================================
Two dimensions of rubric-based verification
================================================================
- The instruction that the agent actually sees, in its entirety, is `current_attempt.user_query`.
- The tests to align with are only `current_attempt.test_patch` and `current_attempt.own_f2p`.
- `patch` and `rationale` are not the primary subjects of rubric judgment; they can at most be used to help you understand what this ATTEMPT is trying to express; do not treat the specific writing of the patch as the requirements themselves.

Dimension A: instruction-test alignment
- There is only one core question: whether the current ATTEMPT's tests faithfully evaluate the current instruction.
- Tests must not be too loose: they cannot miss the core functionality, behavior, or results that the instruction explicitly requires and that the current ATTEMPT attempts to prove through own_f2p or the test forms allowed by the current branch.
- Tests must not be too strict: they cannot introduce additional constraints not stated in the instruction nor reasonably implied, such as additional format requirements, hidden boundary conditions, implementation detail binding, private helper names, fixed intermediate steps, fixed call order, specific refactoring patterns, etc.
- This only checks whether the current ATTEMPT's own `test_patch` and the own tests it is allowed to declare in the current branch are sufficient to prove the functionality it claims to have fixed or added.

- In this branch, the tests body is `current_attempt.test_patch` + `current_attempt.own_f2p`.
- You must strictly check: whether these F2P faithfully prove the core functional change required by the instruction.
- If the instruction clearly requires a code behavioral change but own_f2p / test_patch does not cover the core results, judge `alignment_pass=false`.
- Do not judge as failing just because `own_p2p` is empty; P2P is left for subsequent augment to supplement, and does not belong to the rubric scope of this step.

Dimension B: instruction self-containedness
- Only judge whether the instruction itself is self-contained, that is, whether `current_attempt.user_query` as a complete instruction has already provided the information needed for the agent to understand and complete the task.
- The instruction must not leak oracle solution progress, hidden implementation steps, solution route hints, internal fix directions, preset command sequences, or process-oriented hints like "change this file first then this function".
- The instruction may describe target behavior, user-observable results, public interface contracts, and requirement information that must be known to complete the task; but cannot reverse-inject a specific implementation route into the instruction.

1. Only return a single JSON object, no markdown, no code blocks, no explanations.

6. Issues and feedback must focus on the rubric; do not evaluate code style, naming preferences, or matters unrelated to task quality.
